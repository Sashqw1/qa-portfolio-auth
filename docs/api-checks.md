# Проверка API: базовые кейсы

Учебный материал. У тестируемого сервиса ROBOCALC бэкенда пока нет — данные
приходят из моков на клиенте, поэтому проверять реальные запросы не на чем.
Чтобы отработать навык, кейсы написаны на публичном учебном API
[jsonplaceholder.typicode.com](https://jsonplaceholder.typicode.com) — он открыт,
отвечает всем и подходит для тренировки.

Инструменты: **Postman** для запросов и **DevTools → Network** для разбора того,
что отправляет сам сайт.

## Что смотрим в ответе

| Что проверяем | Зачем |
|---|---|
| Код состояния | 200 при успехе, 201 при создании, 404 если объекта нет — расхождение сразу показывает, что логика на сервере не та |
| Тело ответа | Поля на месте, типы совпадают с ожидаемыми, значения не пустые |
| Заголовки | `Content-Type: application/json` — иначе клиент не разберёт ответ |
| Время ответа | Ориентир для простых запросов — доли секунды; резкий рост стоит отметить |

## Позитивные кейсы

### API-001. Получение записи по идентификатору

```
GET https://jsonplaceholder.typicode.com/posts/1
```

Ожидаем: код `200`, в теле объект с полями `userId`, `id`, `title`, `body`,
поле `id` равно 1.

Фактический ответ:

```json
{
  "userId": 1,
  "id": 1,
  "title": "sunt aut facere repellat provident occaecati excepturi optio reprehenderit",
  "body": "quia et suscipit\nsuscipit recusandae consequuntur expedita et cum..."
}
```

Проверка в Postman, вкладка **Tests**:

```js
pm.test("Код ответа 200", () => pm.response.to.have.status(200));

pm.test("Пришёл JSON", () =>
  pm.expect(pm.response.headers.get("Content-Type")).to.include("application/json"));

pm.test("Поля на месте", () => {
  const body = pm.response.json();
  pm.expect(body).to.have.property("id", 1);
  pm.expect(body.title).to.be.a("string").and.not.empty;
});
```

### API-002. Получение списка

```
GET https://jsonplaceholder.typicode.com/posts
```

Ожидаем: код `200`, массив из 100 элементов, у каждого есть `id`.

```js
pm.test("Это массив и он не пустой", () => {
  const body = pm.response.json();
  pm.expect(body).to.be.an("array").that.is.not.empty;
  pm.expect(body.length).to.eql(100);
});
```

### API-003. Создание записи

```
POST https://jsonplaceholder.typicode.com/posts
Content-Type: application/json

{ "title": "Проверка", "body": "Текст", "userId": 1 }
```

Ожидаем: код `201`, в ответе присвоенный сервером `id`.

## Негативные кейсы

Негативные проверки важнее позитивных: сервис обязан понятно вести себя при
некорректном обращении, а не падать и не отдавать чужие данные.

### API-004. Запрос несуществующего объекта

```
GET https://jsonplaceholder.typicode.com/posts/999999
```

Ожидаем: код `404`, тело пустое. Недопустимо: код `200` с пустым объектом —
клиент примет это за успешный ответ.

### API-005. Некорректный идентификатор

```
GET https://jsonplaceholder.typicode.com/posts/abc
```

Ожидаем: `404` либо `400` с внятным текстом ошибки. Недопустимо: `500` —
это означает, что сервер не проверяет входные данные.

### API-006. Неверный формат тела запроса

```
POST https://jsonplaceholder.typicode.com/posts
Content-Type: application/json

{ "title": }
```

Ожидаем: `400`. Сервер должен отклонить некорректный JSON, а не пытаться его разобрать.

## Чек-лист по любому эндпоинту

| № | Проверка |
|---|---|
| 1 | Успешный запрос возвращает ожидаемый код и структуру |
| 2 | Несуществующий объект — `404`, а не `200` с пустотой |
| 3 | Некорректный тип параметра не приводит к `500` |
| 4 | Обязательные параметры действительно обязательны |
| 5 | Запрос без авторизации к закрытому ресурсу — `401`, а не данные |
| 6 | Чужой идентификатор — `404` или `403`, но не чужие данные |
| 7 | Граничные значения: 0, отрицательное число, очень длинная строка |
| 8 | Повторный одинаковый запрос не создаёт дубль там, где не должен |

## Как это пригодится в ROBOCALC

Когда у сервиса появится бэкенд, список маршрутов уже зафиксирован в
[api-routes.md](https://github.com/Sashqw1/Sashqw1-robocalc/blob/main/api-routes.md).
Первыми проверками станут:

- `PUT /api/projects/{id}/input` — сохранение параметров: ответ `409`, если
  данные правили в другой вкладке, и `422` со списком ошибок по полям;
- `GET /api/projects/{id}` чужого проекта — ожидается `404`, а не `403`,
  чтобы не раскрывать факт существования чужого проекта;
- `POST /api/projects/{id}/simulation` — запуск долгой задачи: ответ с
  идентификатором задания и последующий опрос статуса.
