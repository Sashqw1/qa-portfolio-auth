# BUG-004. Числовое поле показывает одно значение, а в расчёт уходит другое

| Поле | Значение |
|---|---|
| Серьёзность | Major |
| Приоритет | High |
| Компонент | Общий компонент формы `NumberField` (`shared/ui/Field.tsx:119`) |
| Окружение | https://sashqw1.github.io/Sashqw1-robocalc/, Edge 141, Windows 11 |
| Статус | Открыт |
| Найден | Компонентный автотест `NumberField.test.tsx` |

## Описание

Числовое поле принимает ввод как текст и переносит значение в данные только
тогда, когда строка целиком разбирается как число. Если пользователь набрал
«12абв», поле продолжает показывать «12абв», а в состояние формы уходит `12`.
Расхождение ничем не отмечено: ошибки нет, поле выглядит заполненным.

```ts
const normalized = raw.replace(/\s/g, '').replace(',', '.');
if (normalized === '') onChange(null);
else if (!Number.isNaN(Number(normalized))) onChange(Number(normalized));
// иначе значение в состоянии остаётся прежним, а в поле — текст пользователя
```

Поле используется во всей форме параметров объекта и в условиях расчёта
экономики, то есть затрагивает весь ввод числовых данных в сервисе.

## Шаги воспроизведения

1. Открыть шаг 2 «Параметры объекта».
2. В поле «Площадь объекта» очистить значение и ввести `12абв`.
3. Не нажимая ничего другого, перейти к следующему шагу.
4. Сравнить то, что показано в поле, с тем, что используется в расчёте.

Компонентный автотест:

```tsx
await userEvent.clear(input);
await userEvent.type(input, '12абв');
expect(input.value).toBe('12абв');
expect(String(lastValue)).toBe(input.value);
```

## Фактический результат

```
AssertionError: в поле «12абв», в данных «12» — расхождение без предупреждения
Expected: "12абв"
Received: "12"
```

## Ожидаемый результат

Одно из двух: либо недопустимые символы не попадают в поле вообще, либо поле
подсвечивается ошибкой «введите число». Пользователь не должен видеть одно
значение, когда в расчёт идёт другое.

## Влияние

Самый опасный сценарий — опечатка в середине длинного числа: пользователь
видит «12 500ю», считает поле заполненным, а в расчёт уходит 12 500 или 12 —
в зависимости от места опечатки. Проверить это по интерфейсу невозможно.

## Рекомендация

Отклонять ввод недопустимых символов на уровне поля либо хранить «черновик»
и показывать ошибку валидации, пока строка не станет корректным числом.
