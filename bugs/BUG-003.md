# BUG-003. В анализе чувствительности срок окупаемости равен Infinity вместо null

| Поле | Значение |
|---|---|
| Серьёзность | Minor |
| Приоритет | Medium |
| Компонент | Визард, шаг 6 «Сценарии» (`features/wizard/mockEconomics.ts:190`) |
| Окружение | https://sashqw1.github.io/Sashqw1-robocalc/, Edge 141, Windows 11 |
| Статус | Открыт |
| Найден | Автотест `mockEconomics.test.ts` |

## Описание

Контракт `SensitivityResultPoint` описывает поле `resulting_payback_years`
как `number | null`. Когда сценарий не окупается, функция подставляет
`Number.POSITIVE_INFINITY`:

```ts
resulting_payback_years: r.payback_years ?? Number.POSITIVE_INFINITY,
```

Интерфейс этот случай маскирует — таблица чувствительности приводит
нечисловые значения к прочерку (`widgets/SensitivityTable.tsx:22`), поэтому
на экране дефект незаметен. Проявляется он в данных: при сериализации в JSON
`Infinity` превращается в `null`, то есть выгрузка и объект в памяти
содержат разные значения, а потребитель API получит не то, что описано контрактом.

## Шаги воспроизведения

1. Задать условия, при которых сценарий не окупается: стоимость замещаемого
   персонала 0 ₽/мес, состав оборудования — 50 единиц.
2. Перейти на шаг 6 «Сценарии», открыть анализ чувствительности.
3. Выгрузить результат расчёта в JSON либо посмотреть объект в консоли браузера.

Автотест:

```ts
const points = computeSensitivity(d(0), DEFAULT_SCENARIOS[1]);
points.forEach((p) => console.log(p.parameter, p.resulting_payback_years, Number.isFinite(p.resulting_payback_years)));
```

## Фактический результат

```
точка: Стоимость оборудования | payback = Infinity | тип: number | конечное: false
точка: Стоимость персонала    | payback = Infinity | тип: number | конечное: false
точка: Коэффициент загрузки   | payback = Infinity | тип: number | конечное: false
```

При `JSON.stringify` те же поля становятся `null` — значения в памяти и в выгрузке расходятся.

## Ожидаемый результат

`resulting_payback_years === null`, как указано в контракте. Значение одинаково
в интерфейсе, в памяти и в выгрузке.

## Влияние

Пока сервис работает на моках, влияние ограничено. После подключения бэкенда
и экспорта отчётов расхождение приведёт к разным данным в интерфейсе и в выгрузке,
а защита на стороне таблицы — обходной приём, скрывающий причину.

## Рекомендация

Убрать подстановку `Number.POSITIVE_INFINITY`, возвращать `null` напрямую:
`resulting_payback_years: r.payback_years`.
