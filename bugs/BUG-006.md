# BUG-006. Валидация параметров пропускает значение NaN

| Поле | Значение |
|---|---|
| Серьёзность | Minor |
| Приоритет | Low |
| Компонент | Валидация формы параметров (`features/wizard/paramsSchema.ts:228`) |
| Окружение | https://sashqw1.github.io/Sashqw1-robocalc/, Edge 141, Windows 11 |
| Статус | Открыт |
| Найден | Проверка граничных значений функции `validateParams` |

## Описание

Проверка числового поля устроена так:

```ts
if (f.kind === 'number' && typeof v === 'number') {
  if (f.min !== undefined && v < f.min) { ... }
}
```

`typeof NaN === 'number'`, при этом любое сравнение с `NaN` даёт `false`,
поэтому значение проходит все ветки проверки и считается корректным.
Поле обязательное, но `NaN` не пустой — проверка обязательности тоже пропускает.

## Шаги воспроизведения

Через интерфейс `NaN` ввести нельзя — поле блокирует нечисловой ввод (см. BUG-004),
поэтому проверка выполнена на уровне функции валидации:

```ts
validateParams('warehouse', { ...base, area_sqm: Number.NaN });
```

## Фактический результат

```
NaN в числовом поле -> замечаний нет
```

Валидация не возвращает ни ошибки, ни предупреждения.

## Ожидаемый результат

`NaN` отклоняется как некорректное значение: «Введите число».

## Влияние

Сейчас дефект недостижим через интерфейс, поэтому приоритет низкий. Он станет
актуальным при появлении импорта из Excel и CSV — такая кнопка на шаге 2 уже
есть (пока заглушка). Пустая ячейка или текст в числовой колонке при разборе
легко превращаются в `NaN`, и дальше расчёт получит значение, которое
валидация признала допустимым.

## Рекомендация

Добавить проверку `Number.isFinite(v)` в начало ветки числовых полей.
