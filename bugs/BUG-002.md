# BUG-002. ROI подставляется константой 999 % вместо расчётного значения

| Поле | Значение |
|---|---|
| Серьёзность | Minor |
| Приоритет | Medium |
| Компонент | Визард, шаг 5 «Экономика» (`features/wizard/mockEconomics.ts:149`) |
| Окружение | https://sashqw1.github.io/Sashqw1-robocalc/, Edge 141, Windows 11 |
| Статус | Открыт |
| Найден | Автотест `mockEconomics.test.ts` |

## Описание

Когда единовременные вложения равны нулю, а годовой эффект положителен,
показатель ROI не вычисляется, а подставляется фиксированным числом 999 %.
Такой случай реален для сценария RaaS: техника берётся по подписке, CAPEX
близок к нулю или равен ему.

В коде:

```ts
const roi = capexTotal > 0
  ? ((effect * horizon - capexTotal) / capexTotal) * 100
  : effect > 0 ? 999 : 0;
```

## Шаги воспроизведения

1. Дойти до шага 5 «Экономика».
2. Выбрать способ финансирования «RaaS» при пустом составе оборудования
   (единовременные вложения обнуляются).
3. Нажать «Рассчитать» и посмотреть показатель ROI.

Автотест:

```ts
const r = computeScenario(draft({ selected: [], quantities: {} }), DEFAULT_SCENARIOS[2]);
expect(r.roi_pct).not.toBe(999);
```

## Фактический результат

```
AssertionError: ROI = 999 — магическая константа вместо расчёта: expected 999 not to be 999
```

В интерфейсе выводится «ROI 999 %».

## Ожидаемый результат

При нулевых вложениях показатель ROI не определён — в этом случае корректно
выводить прочерк или пояснение «вложений нет, показатель неприменим»,
а не правдоподобное на вид число.

## Влияние

999 % выглядит как результат расчёта и может попасть в отчёт для руководства.
Значение не связано с реальными данными проекта и вводит в заблуждение.

## Рекомендация

Возвращать `null` для ROI при нулевых вложениях и отображать прочерк с подсказкой,
как это уже сделано для срока окупаемости («годовой эффект ≤ 0»).
