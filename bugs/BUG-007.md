# BUG-007. На экране уже 1366 px интерфейс обрезается без предупреждения

| Поле | Значение |
|---|---|
| Серьёзность | Trivial |
| Приоритет | Low |
| Компонент | Раскладка приложения, все экраны |
| Окружение | https://sashqw1.github.io/Sashqw1-robocalc/, Edge 141, окно 375×667 |
| Статус | Открыт |
| Найден | Снимки экрана в контрольном разрешении |

## Описание

Нефункциональные требования заявляют работу от 1366×768, и в этом разрешении
интерфейс действительно собран корректно. На узких экранах раскладка не
перестраивается: содержимое обрезается по ширине, появляется горизонтальная
прокрутка, часть управляющих элементов уходит за пределы экрана. При этом
приложение открывается как обычно и ничего не сообщает пользователю.

## Шаги воспроизведения

1. Открыть https://sashqw1.github.io/Sashqw1-robocalc/projects/p-leningradka/wizard/params?as=user
2. Задать окну браузера ширину 375 px (режим эмуляции устройства в DevTools).
3. Попробовать дойти до кнопки «Далее: подбор».

## Фактический результат

Видна левая часть страницы, правая колонка формы и подсказка недоступны,
кнопки навигации визарда вынесены за пределы видимой области.
Снимок экрана: [screenshots/BUG-007-wizard-params-375.png](../screenshots/BUG-007-wizard-params-375.png)

Для сравнения — тот же экран в целевом разрешении:
[screenshots/wizard-params-1366.png](../screenshots/wizard-params-1366.png)

## Ожидаемый результат

Одно из двух: либо раскладка перестраивается в одну колонку, либо приложение
сообщает о минимальном поддерживаемом разрешении — чтобы пользователь понимал,
что видит не ошибку, а ограничение.

## Влияние

Формально требование не нарушено: разрешение ниже заявленного. Но пользователь,
открывший ссылку с телефона, увидит сломанную страницу без объяснений —
это вопрос доверия к сервису, а не только вёрстки.

## Рекомендация

Добавить заглушку с текстом о минимальном разрешении либо простую одноколоночную
раскладку для узких экранов.
