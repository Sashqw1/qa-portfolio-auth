# BUG-001. Расчёт показывает годовую экономию при пустом составе оборудования

| Поле | Значение |
|---|---|
| Серьёзность | Major |
| Приоритет | High |
| Компонент | Визард, шаг 5 «Экономика» (`features/wizard/mockEconomics.ts`) |
| Окружение | https://sashqw1.github.io/Sashqw1-robocalc/, Edge 141, Windows 11 |
| Статус | Открыт |
| Найден | Автотест `mockEconomics.test.ts` |

## Описание

Если из состава оборудования исключить все позиции, сценарий «Покупка» всё равно
показывает положительный годовой эффект и конечный срок окупаемости. Экономия
возникает из ничего: роботов не куплено, но расчёт утверждает, что предприятие
экономит 260 000 ₽ в год.

Причина — в модели базовый OPEX включает постоянную статью «прочие расходы»
(2 600 000 ₽), которая в сценарии с роботизацией заменяется расходами на технику.
При пустом составе эти расходы равны нулю, и разница целиком засчитывается в эффект.

## Шаги воспроизведения

1. Открыть проект и дойти до шага 4 «Сравнение».
2. Снять отметки со всех позиций оборудования — состав пуст.
3. Перейти на шаг 5 «Экономика», нажать «Рассчитать».
4. Посмотреть показатели «Годовой эффект» и «Срок окупаемости».

Автотест, воспроизводящий дефект без интерфейса:

```ts
const r = computeScenario(draft({ selected: [], quantities: {} }), DEFAULT_SCENARIOS[1]);
expect(r.annual_effect).toBeLessThanOrEqual(0);
```

## Фактический результат

```
AssertionError: expected 260000 to be less than or equal to 0
```

Годовой эффект — 260 000 ₽, срок окупаемости рассчитан и выведен как достижимый.

## Ожидаемый результат

При пустом составе оборудования годовой эффект равен нулю либо отрицателен,
срок окупаемости — «не окупается», а шаг 5 сообщает, что считать нечего:
на шаге 4 уже выводится предупреждение о пустом составе, но расчёт его игнорирует.

## Влияние

Пользователь может получить обоснование инвестиций, которое не опирается ни на
одну единицу техники. Для сервиса, который готовит материалы для принятия
инвестиционного решения, это искажение сути: цифры выглядят достоверно,
но не связаны с составом проекта.

## Рекомендация

Прекращать расчёт при пустом составе оборудования либо исключить статью
«прочие расходы» из сравнения, если роботизация фактически не внедряется.
